### Phase 2 verification notes
- **Npcap SDK substitute:** the Npcap *runtime* ships no `wpcap.lib`, and the SDK download was unreachable. `vendor/npcap/lib/wpcap.lib` is generated from the installed `wpcap.dll` by `scripts/generate-wpcap-lib.ps1`; `build.rs` adds it to the link search path. An official SDK on `LIB` still takes precedence.
- **Live capture requires elevation.** Without Administrator rights Npcap hangs `pcap_findalldevs`; the engine's 5s watchdog turns that into an actionable error instead of a frozen window. Confirm end-to-end with an elevated shell:
  `cargo run --example capture_smoke -- 8` (prints interfaces, decoded protocol mix, and resolved DNS/SNI hosts), then `npm run tauri dev`.
- **QUIC SNI is intentionally absent.** The ClientHello sits in an AEAD-encrypted CRYPTO frame; extracting it needs HKDF+AES-GCM on the capture path. QUIC is still detected and labelled, and TLS-over-TCP supplies SNI for most browsing.

### Phase 3 verification notes
- **Attribution is verified live and does not need elevation.** `cargo run --example attribution_smoke -- 25` reads the real OS connection table and prints the owning process and Windows user per row. On this machine it resolves every row to a PID and user-owned processes to `OMEN\Vraj Vaghela`; cached re-resolution of 25 rows takes ~12µs, confirming the syscalls are not on the per-packet path.
- **Unelevated runs show `<unknown>` for service processes.** `OpenProcess` is denied for processes owned by other accounts, so their PID resolves but the image path and token do not. Running elevated (which capture requires anyway) fills those in.
- **Sockets with owner PID 0 are deliberately unattributed.** Windows reports PID 0 for TIME_WAIT remnants; indexing those would blame the Idle process for live traffic.
- **The remaining live check** is the same elevated run Phase 2 needs: `npm run tauri dev`, start capture, then confirm the Connections view fills with attributed rows within ~1s and that filters isolate them. Everything after decode is already covered offline by `cargo test --test flow_pipeline`, which pushes real fixture frames through aggregation, attribution, the Connections DTO, and the `flows` table.

### Phase 4 verification notes
- **Enforcement costs nothing until a rule blocks.** The network-layer handle is opened only while an enabled block rule exists and closed again when the last one is disabled, so the default allow-and-observe posture (`architecture.md` §5 rule 7) never puts packets through userland. The SOCKET-layer handle stays open regardless — it is sniff-only and exists to sharpen attribution.
- **Everything fails open.** A missing driver, a denied open, or a dead handle closes the handle (WinDivert reinjects whatever it queued) and records an actionable message that the engine-status pill shows as "Capture only". Verified unelevated: `cargo run --example enforcement_smoke -- 3` reports *"the WinDivert driver could not be opened (Running without elevated access rights)"*.
- **The remaining live check needs elevation.** In an elevated shell: `cargo run --example enforcement_smoke -- 20 <remote ip> 443` creates a temporary block rule (in a scratch database), prints socket-event and blocked-packet counters each second, then disables the rule so traffic recovers — the two halves of the exit criterion. Then `npm run tauri dev` to confirm the pill reads "Enforcing N rules" and that blocked connections show the danger tint, Blocked badge and rule name.
- **SNIFF is mandatory on the socket handle.** A socket-layer handle opened without it *blocks* the operations it matches, which would break every connection on the machine. The crate's `socket_default()` flags omit SNIFF, so the flags are built explicitly.
- **Loopback is excluded from enforcement.** Diverting it would put Cognton between local-only services (including the Vite dev server) and the stack for no security benefit.
- **One packet per receive, deliberately.** `library_docs.md` §4 puts correctness first here, so the loop does a single `recv_wait`/`send` rather than batching with `recv_wait_ex`/`send_ex` — the batched path would have to re-coalesce a partially-filtered buffer, and a mistake there breaks connectivity. Batching belongs with the Phase 6 performance pass.
- **Blocked marking needs capture running.** Enforcement never creates flow rows (`architecture.md` §5 rule 4); it marks the row the Npcap path already made. Counters and `hit_count` are independent of capture.
- **The rules manager UI is Phase 5.** Phase 4 shipped the engine, the IPC surface, blocked marking, and the status pill; rule CRUD from the UI landed in Phase 5 (see below).
- **WinDivert build wiring.** `windivert` is pinned to `=0.7.0-beta.4` (pre-1.0, breaking below 1.0). `.cargo/config.toml` points `WINDIVERT_PATH` at `vendor/windivert/WinDivert-2.2.2-A/x64`, and `build.rs` stages `WinDivert.dll` + `WinDivert64.sys` into the profile's root, `deps/` and `examples/` directories — the DLL is a static import, so every binary needs it beside the executable and the DLL loads its driver from its own folder. Bundling them into the installer is Phase 6.

### Phase 5 verification notes
- **The light palette could not meet `ui_rules.md` §10 as specified, so `ui_tokens.md` was amended.** A measured audit found 24 failing pairs — protocol badge labels as low as 1.84:1 against a 4.5:1 requirement, and chart marks at 1.96:1 against 3:1. These were in the specified palette, not in how it was used. Per `agents.md` Golden Rule 4 this was raised rather than silently changed; the chosen fix adds a paired `--<token>-strong` for every semantic and protocol colour (`ui_tokens.md` §1.1). **Tinted fills keep their exact original colour** — only ink and solid marks move — so the aesthetic is unchanged while every pair now passes. `--foreground-subtle` and the dark `--danger-foreground` also moved; dark mode needed only two distinct `-strong` values, confirming that half of the palette was already sound.
- **Contrast is now a test, not a judgement call.** `scripts/check-contrast.mjs` enumerates the 51 token pairs the components actually render — naming the real class combination for each — composites `/8`, `/10` and `/15` tints the way the browser does, and asserts §10's thresholds in both themes. It runs as part of `npm test` and exits non-zero on regression. Borders are deliberately excluded: §4 specifies them as 1px decoration, and no state is carried by a border alone (an invalid field pairs `border-danger` with text; focus uses the 2px `--ring`, which is asserted).
- **The rules UI never writes without a confirmation step.** Every path — the Add rule button, a Connections row menu, the inspector footer — ends in the same prefilled dialog, and the draft commands (`draft_rule_from_flow`, `draft_rule_from_packet`) touch no database. `create_rule_from_flow` remains in the IPC surface for one-step creation but the UI deliberately does not use it: `architecture.md` §5 rule 7 wants blocking explicit.
- **Criteria are still derived in Rust.** `draft_rule_from_packet` maps the packet to its `flow_id` and reuses the flow builder, so a rule built from a packet and one built from its Connections row cannot differ. Packets with no flow (ARP, or frames decoded after their conversation retired) get an actionable message instead of an empty form.
- **Form validation is mirrored, not moved.** `features/rules/rule-criteria.ts` repeats the limits from `ipc/dto/rule.rs` so the user sees the problem in the field; Rust re-validates and its rejection is surfaced above the form. The TS address check is deliberately lenient — shape only — so it can never reject something the Rust matcher would accept.
- **The overview derives from streamed state only.** Counts, top talkers and protocol shares are one pass over the live flow store (`features/overview/overview-metrics.ts`); no decoding, matching or attribution happens in TS (`architecture.md` §5 rule 6). Throughput is sampled from the existing stats messages at 1 Hz — the series keeps its array identity between samples, so the chart repaints once a second rather than at the stream's 15 Hz.
- **Flow seeding moved into `useCaptureController`.** The stream only carries diffs, so whichever view mounts first now seeds the table from `list_flows` exactly once per session; before this the snapshot only happened on the Connections page.
- **New dependencies:** `recharts@3.10.1` (the charting choice recorded in `architecture.md`, used only for the sparkline) and dev-only `jsdom` + `@testing-library/react` for the rule-form component test `code_standards.md` §5 asks for. The production bundle is 613 kB (189 kB gzip); it loads from disk in a webview, so code-splitting it is a Phase 6 nicety, not a problem. The pre-existing `npm audit` findings are all in the vite/vitest dev chain.
- **The remaining live check needs elevation.** In an elevated shell run `npm run tauri dev`, start capture, then: confirm the Overview fills within a second or two and the sparkline tracks browsing; right-click a Connections row and create a block rule for a live endpoint (the connection should stall and the row gain the danger tint, Blocked badge and rule name); toggle the rule off and confirm traffic recovers and the switch, hit count and dropped-packet counters agree.

### Phase 6 verification notes
- **The bundled-resource layout was wrong and is fixed.** `bundle.resources` was an array of `../vendor/...` paths. Tauri v2 rewrites `..` to a literal `_up_` segment and preserves the rest of the structure, so the files would have installed to `<install>\_up_\vendor\windivert\WinDivert-2.2.2-A\x64\`. `WinDivert.dll` is a **static import** of `windivert-sys`, and the Windows loader resolves those from the executable's own directory (step 7 of the search order) — never from an arbitrary subfolder — so the installed app would have failed to start with a missing-DLL box before any Rust code ran. The map form with an empty-string target (`"…/WinDivert.dll": ""`) places both files directly in `$RESOURCE`, which on Windows *is* the exe directory. `WinDivert64.sys` must sit beside the DLL because `WinDivertOpen` loads its driver relative to the DLL's own location. The same rules apply under `tauri dev`, so `src-tauri/target/debug/` is where to confirm this without building an installer.
- **Npcap cannot be bundled.** Its licence forbids redistribution outside a paid OEM agreement, so the installer can only *require* it — the health diagnostics and the enumeration watchdog are how a missing driver is surfaced. `build_plan.md` Phase 6 says "bundles/prompts for Npcap + WinDivert"; bundling is possible for WinDivert only, and the "prompt" is the actionable error state rather than an installer step. Raised rather than silently reinterpreted (`agents.md` Golden Rule 4).
- **The soak test now proves what it claims.** The first version pushed 50,000 copies of one hand-assembled TCP segment, so it exercised a single classifier and never touched the caps it was supposed to defend. It now round-robins six real fixture frames (HTTP, TLS+SNI, bare TCP SYN, DNS, QUIC, mDNS) over 251 remote hosts, asserts every classifier still agrees, and asserts the bounds Phase 6 rests on: `ring.len() <= 20_000` on every iteration, live flows within the LRU cap, and the port-80 block rule matching exactly the HTTP passes and nothing else. A second test drives 2× the cap in unique 5-tuples to confirm eviction is bounded *and* not over-aggressive, and that `snapshot()` (what the UI seeds from) agrees with `active_count()`. The cap under test is imported from `flow::DEFAULT_CAPACITY` so it cannot drift from production.
- **Retention limits are unit-tested, not just asserted in prose.** `validate_retention` is split out of the command and covers the defaults, both inclusive bounds, zero (which would silently disable retention), and over-ceiling values; the error messages are asserted to name the offending field, since the UI surfaces them verbatim. `FlowHistoryWriter` previously cached the policy at construction — a Settings change only applied after a capture restart. It now re-reads on each prune.
- **`get_system_health` reported a filename, not a path.** `databasePath` was the hard-coded string `"cognton.sqlite3"`, which was actively misleading in the fallback case (`%TEMP%\cognton-fallback`). `Store` now keeps its resolved path and the diagnostic shows it.
- **Settings page now uses the shared primitives.** It had two raw `<input>` elements with hand-rolled border/background classes and a `text-[11px]` size that is not in `ui_tokens.md` §2, plus `text-h3`, which does not exist in the Tailwind theme (it silently rendered at the inherited size). These are now `Input` (with `mono`, `aria-describedby` on the notes) and real `text-h2`/`text-h1` mono values, and the loading branch is a `Skeleton` rather than a bare text line (`ui_rules.md` §9). `grep` for `#hex`, `[Npx]` and `[Nrem]` in `src/` is clean again.
- **Scrollbars were the last unstyled surface.** Every scroll container was rendering the platform default — light track, stepper arrows, square corners — which is the one piece of chrome the app doesn't otherwise draw and read as unfinished against a dark Geist panel. They are now tokenized globally (`ui_tokens.md` §7, `ui_rules.md` §11): transparent track, a 6px `--radius` pill inset inside a 12px hit target, no steppers. Two things worth recording: the standard `scrollbar-width`/`scrollbar-color` pair **cannot** be used alongside `::-webkit-scrollbar-*` — in Chromium, setting either standard property makes the engine discard the pseudo-elements and draw its own bar, and only the pseudo-elements can drop the steppers and inset the thumb. And the thumb needed its own neutral pair rather than an existing token: `border-strong` is 1.6:1 on dark `surface`, well under the 3:1 a UI mark owes §10. Because the track is transparent the thumb is asserted against all three surfaces it can cross (`background`, `surface`, `surface-muted`); the tightest is 3.40:1 light / 3.68:1 dark, and the four new pairs took the check from 94 to 102.
- **Table headers were misaligned with their bodies, by exactly one scrollbar.** A sticky header doesn't scroll, so it never loses width to the bar the way its body does — every right-aligned column (Bytes, Duration, Hits) sat off from its values, visible in all three tables. Fixed structurally rather than by nudging: bodies take `.scrollbar-gutter-stable` so the gutter is reserved whether or not the rows currently overflow, and headers take `pr-table-gutter` (`calc(0.75rem + var(--scrollbar-size))`) to match. Reserving unconditionally is what makes the pair correct in both states — otherwise a table that grows past its height would shift every column mid-stream, which is exactly what the live table does several times a second.
- **The remaining live check is the elevated run Phases 2–5 also need**, plus a real packaging pass: `npm run tauri build`, install the NSIS output on a clean Win10/11 VM with Npcap present, and confirm the app launches elevated, that `WinDivert.dll`/`WinDivert64.sys` sit next to `Cognton.exe`, and that the Settings health card reads Administrator / Online / Ready / Observing.
